# 开发与交付计划

状态：`Draft v0.1`  
人员假设：1 名有经验的全栈开发者，配合 Codex/LLM 研发辅助  
MVP 目标：10～14 周

## 1. 执行原则

- 新建独立仓库，不从当前应用复制代码、数据库或前端设计。
- 文档先冻结业务边界，随后只做端到端纵向切片。
- 每一阶段必须通过对应 Gate，未通过不得继续扩大范围。
- 先验证一篇真实文章和一只真实股票，再扩展批量和自动化。
- 阶段完成包括 Web、API、领域、持久化、Worker、测试和文档，不接受只有后端的“完成”。
- 不以模拟成功页面代替真实数据与失败状态。

## 2. 里程碑总览

| 阶段 | 周期 | 结果 |
|---|---:|---|
| P0 产品与技术基线 | 3～5 天 | 契约、原型、真实样本、供应商试验完成 |
| P1 可运行骨架 | 1 周 | 新仓库、Web/API/Worker/DB、设置和健康状态 |
| P2 文章到结构化研究 | 2 周 | 真实文章自动分类、证据、概念和候选假设 |
| P3 数据与回测闭环 | 2～3 周 | 日线数据、规则 DSL、分级回测、可复现报告 |
| P4 股票分析与今日页 | 2 周 | 单股建议、持仓风险、每日候选和解释 |
| P5 自动演进与例外 | 1～2 周 | 后台模拟、暂停、升级、周报、例外收件箱 |
| P6 稳定化与验收 | 2～3 周 | UX、性能、安全、恢复和真实场景验收 |

阶段可以在风险可控时局部并行，总体 MVP 仍以 10～14 周为目标。稳定个人使用版本预计 14～20 周。

## 3. P0：产品与技术基线

交付：

- 本文档集评审并冻结 v1 边界。
- 三个核心页面低保真原型和首次设置原型。
- 10～20 篇代表性真实文章评测集，包含无效、模糊、重复和冲突样本。
- 代表性 A 股固定行情样本和预期信号。
- LLM 结构化输出、证据定位和成本实验。
- 至少两个行情数据源的覆盖、许可、时点和稳定性对比。
- Rule DSL v0 和 RecommendationFacts Schema v0。

退出条件：关键契约可以支持完整演示，不存在必须依赖旧系统运行时的事项。

## 4. P1：可运行骨架

纵向切片：首次设置 → 保存风险政策 → 打开空的“今天”页。

任务：

- 初始化单仓库，建立 Web、API、Domain、Infrastructure、Worker 包。
- 建立 PostgreSQL 迁移和本地开发启动方式。
- 实现持久化任务队列、Worker 租约和幂等基础。
- 实现用户设置和 RiskPolicyVersion。
- 建立 LLM、行情和通知 Adapter 接口及假实现。
- 建立结构化日志、健康检查和测试基线。
- 完成极简初始化与三入口应用壳。

Gate：全新环境一条命令启动；设置可完成；前后端、数据库和 Worker 健康状态真实可见。

## 5. P2：文章到结构化研究

纵向切片：提交一篇真实文章 → 自动分类 → 查看证据和处理摘要。

任务：

- 文本粘贴和文件上传；链接获取在来源契约验证后实现。
- 内容规范化、指纹、完全重复和近似重复候选。
- 分类、证据与声明提取 Schema。
- 概念分析和有限量化假设生成。
- Schema、证据定位和领域验证。
- AI 回归评测集与模型/提示词版本记录。
- “我的交易员”文章入口和业务状态。
- 重试、永久失败和不打扰用户的归档路径。

Gate：代表性评测集达到既定证据准确率；无依据补全为 0；无用文章不会产生规则；用户不操作中间阶段。

## 6. P3：数据与回测闭环

纵向切片：一条候选规则 → 数据需求 → 编译 → 分级回测 → 结果或明确阻断。

任务：

- 确定一个正式行情供应商，冻结规范化契约。
- 交易日历、证券主数据、日线、复权和交易状态同步。
- 数据质量、覆盖、可用时间和版本化。
- 受限 Rule DSL、编译器和静态时间安全检查。
- 固定样本、向量化信号和事件驱动组合模拟。
- T+1、涨跌停、停牌、成本和滑点模型。
- 分级验证、样本外、滚动验证和制品缓存。
- Worker 资源限制与前台优先级。

Gate：真实规则在全新环境可确定性复现；故意注入未来数据、缺失行情和不可成交条件时必须被阻断或正确模拟。

## 7. P4：股票分析与今日页

纵向切片：输入股票和持仓 → 确定性事实 → AI 解释 → 后续复盘。

任务：

- MarketSnapshot、PositionSnapshot 和 RecommendationFacts。
- 市场状态识别与 Playbook 规则匹配。
- 风险政策最终门和明确拒绝状态。
- 股票分析页面及渐进披露证据。
- 今日持仓风险和全市场候选扫描。
- AI 解释器，严格禁止改变确定性事实。
- 用户执行记录和基础 OutcomeReview。
- 数据新鲜度、建议有效期和撤销机制。

Gate：一只真实股票完整走通；数据过期或不完整时不生成假建议；新用户能在 30 秒内发起分析。

## 8. P5：自动演进与例外

纵向切片：通过验证的规则 → 后台模拟 → 升级提案 → 用户确认 → 新 Playbook → 可回滚。

任务：

- ShadowObservation 和当前市场模拟。
- 规则健康监控、市场环境切片和自动暂停。
- EvolutionProposal、影响摘要和回滚。
- 例外去重、优先级和一次一个问题。
- 日摘要与周度进化报告。
- CapabilityVersion 和 LLM 回归比较。
- 等待数据的研究任务自动重试。

Gate：正常研究不产生用户待办；重大规则不能静默启用；暂停和回滚真实有效。

## 9. P6：稳定化与验收

任务：

- 非开发用户可用性测试和任务计时。
- 375/768/1024/1440px 浏览器验证。
- 前台与后台并发压力、内存和磁盘容量测试。
- 供应商失败、任务崩溃、断网和数据库恢复演练。
- API Key、日志脱敏、依赖和输入安全审查。
- 数据备份、导出、恢复和升级回滚。
- 完整真实场景验收、已知风险和用户操作说明。

Gate：所有质量门禁通过，残余风险明确且不破坏产品边界。

## 11. 测试策略

- 单元测试：规则表达式、状态机、风险政策、时间语义和指标。
- 属性测试：数据边界、规则 DSL 和不可变量。
- 固定夹具：预期信号、成交、T+1、涨跌停、停牌和复权。
- 集成测试：PostgreSQL、Parquet、Worker 租约、迁移和适配器契约。
- AI 回归：固定文章、Schema、证据定位、无依据补全和提示注入。
- E2E：初始化、导入文章、分析股票、处理升级和失败恢复。
- 浏览器测试：响应式、键盘、可访问名称、真实错误和空状态。
- 性能测试：今日页、单股分析、全市场扫描和后台回测资源隔离。

## 12. 变更纪律

- 每个阶段使用独立验收清单和证据。
- 任何新功能必须说明它服务哪个用户任务；否则不进入 MVP。
- 新数据源必须由已经接受的 DataRequirement 驱动。
- 新模型或提示词必须有回归结果。
- 修改规则语义必须产生新版本和迁移说明。
- 不以关闭测试、降低门槛或隐藏错误来通过阶段。
