# 验收标准与质量门禁

状态：`Draft v0.1`

## 1. 门禁规则

- Gate 是进入下一阶段的必要条件，不能通过修改测试期望掩盖失败。
- 验收证据必须来自可重复命令、固定夹具或浏览器记录。
- “接口返回 200”不代表业务成功。
- 每个 Gate 记录版本、环境、数据校验和、结果和残余风险。
- 任何涉及真实建议的失败优先于功能数量。

## 2. G0 产品边界

通过条件：

- 三个主入口和 v1 非目标已经冻结。
- A 股、日线、收盘后、人工执行边界明确。
- 首批真实文章和股票用例已选定。
- 不存在必须复制旧代码、旧数据库 Schema 或旧前端的要求。
- 所有利益相关方同意“系统可以拒绝给出建议”。

## 3. G1 可运行与可恢复

通过条件：

- 全新环境按文档可以启动 Web、API、Worker 和数据库。
- 空数据库迁移和升级、降级路径经过测试。
- Worker 崩溃后任务可以安全重领，不重复产生业务结果。
- 外部服务断开时显示真实状态。
- 重启后已接受状态不丢失。

## 4. G2 AI 与证据

通过条件：

- 所有 AI 输出通过版本化 JSON Schema。
- 每条提取声明均有可重新定位的原文证据。
- 评测集中的无依据补全为 0。
- 无用和营销文章不会生成可执行规则。
- 重复文章不会产生重复正式规则。
- 提示注入文本不能改变工具权限或系统边界。
- 模型不可用时任务保持可恢复，不伪造处理完成。

## 5. G3 规则与数据安全

通过条件：

- 规则 DSL 不允许任意代码执行。
- 每个输入字段包含频率、单位和可用时间要求。
- 数据覆盖、质量、粒度、复权或时间安全失败时回测被阻断。
- 故意加入未来数据的测试被检测并失败。
- 相同版本输入产生相同信号和校验和。
- 回测和在线分析共享同一规则执行逻辑。

## 6. G4 回测真实性

通过条件：

- T+1、停牌、涨跌停、退市、成本和滑点有固定预期夹具。
- 训练、验证和样本外区间明确分离。
- 报告所有尝试候选，不只保存成功候选。
- 至少按年份、市场环境和股票特征分层展示稳定性。
- 参数邻域不存在仅单点有效的异常峰值，或该风险被明确拒绝。
- 完整回测可以由清单和校验和重建。

## 7. G5 建议安全

通过条件：

- 每条建议有行情截止时间、有效期、动作条件、失效条件和风险。
- 建议引用 Playbook、规则、风险政策和数据版本。
- 风险政策能够否决策略信号。
- 数据过期、缺失或规则不适用时明确拒绝建议。
- LLM 解释不能改变 RecommendationFacts 中任何受控字段。
- 已生成建议不可静默改写；数据错误时使用撤销事件。

## 8. G6 自动化与演进

通过条件：

- 代表性文章集中至少 90% 不需要用户处理。
- 验证失败、重复、无效和等待数据均能自动处置。
- 新规则先回测再模拟，未经确认不能进入正式 Playbook。
- 规则出现严重数据或风险问题时可以自动暂停。
- 升级提案包含影响、证据和回滚目标。
- 用户不响应升级时，当前正式版本继续安全运行。

## 9. G7 UX

使用未阅读文档的测试者：

- 90% 以上在 3 分钟内完成初始化。
- 90% 以上在 30 秒内发起股票分析。
- 90% 以上在 1 分钟内提交文章。
- 能正确复述当前建议、触发条件和最主要风险。
- 正常路径每项任务不超过三次操作。
- 主导航不超过三个入口；页面不显示内部工程对象。
- 没有例外时，测试者明确知道无需操作。

浏览器要求：

- 375、768、1024、1440px 无横向溢出和遮挡。
- 键盘可完成全部核心任务。
- 输入有可见标签，焦点可见，状态不只依赖颜色。
- 正文对比度达到 4.5:1，减弱动态偏好得到尊重。

## 10. G8 性能与资源隔离

目标机器为 8 核 CPU、16 GB 内存、SSD：

- 已缓存今日页 P95 < 2 秒。
- 单股确定性分析 P95 < 5 秒。
- 文章提交 P95 < 2 秒。
- 后台完整回测期间，前台 P95 不超过正常值的 1.5 倍。
- Worker 遵守配置的 CPU、内存和并发上限。
- 磁盘接近阈值时停止非关键制品生成并告警，不损坏已接受结果。

## 11. G9 安全、隐私与运维

通过条件：

- 密钥不进入代码、数据库明文字段、日志或回测制品。
- 上传文件进行类型、大小、内容和路径安全检查。
- 外部文章内容不能发起任意工具调用。
- 个人持仓和建议导出、备份、恢复经过测试。
- 数据库迁移可回滚或有明确前滚恢复方案。
- 依赖漏洞、权限和日志脱敏检查通过。
- 健康页能区分 Web、DB、Worker、行情和 LLM 状态。

## 12. 最终场景验收

至少用以下场景走通：

1. 明确规则文章成功进入模拟。
2. 模糊文章自动产生有限候选并淘汰不稳定定义。
3. 无用文章自动归档。
4. 重复文章合并证据。
5. 缺少数据的文章进入等待队列，不阻塞其他任务。
6. 有持仓股票给出条件化建议并在后续自动复盘。
7. 行情过期时拒绝建议。
8. 正式规则因数据异常自动暂停。
9. 通过模拟的新版本形成一次性升级确认并能回滚。
10. 外部 LLM 或行情服务中断后安全降级并恢复。

## 13. 发布判定

只有 G0～G9 全部通过且最终场景无 P0/P1 缺陷时，MVP 才能标记为可用。

允许带入发布的风险必须：

- 不突破安全、数据时点和用户决策边界。
- 有明确影响范围、规避方法、负责人和解决时间。
- 在产品内如实呈现，不依赖口头说明。
