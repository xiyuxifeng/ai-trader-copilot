# 行情、回测与性能方案

状态：`Draft v0.1`

## 1. 为什么必须回测

文章提炼出的内容首先是研究假设。没有回测和样本外验证，系统无法判断：

- 观点是否只有叙事吸引力。
- 收益是否来自更高风险、幸存者偏差或未来信息。
- 交易成本后是否仍有意义。
- 参数是否只适用于一小段历史。
- 规则在哪种市场环境和持有周期中有效。

回测是规则进入后台模拟的必要条件，但不是未来盈利证明。

## 2. v1 数据范围

v1 行情只使用不要求付费订阅的来源，并在本地保存经过质量门的不可变版本。旧电脑历史数据只允许一次性导入，不作为运行依赖。免费源不能可靠支持的分钟、逐笔和 Level-2 数据不进入 v1。

基础数据：

- A 股证券主数据和上市、退市区间。
- 交易日历。
- 日线开高低收、成交量和成交额。
- 复权因子和公司行为。
- 停牌、涨跌停和特殊交易状态。
- 指数日线，用于市场环境与基准。

可选数据只有在真实规则需求出现后才接入，例如财务、行业、公告或资金流。不得先建设没有规则需求的数据管道。

## 3. 数据契约

每个供应商适配器输出统一记录：

- `instrument_id`
- `trading_date`
- `open/high/low/close`
- `volume/turnover`
- `adjustment_factor`
- `trade_status`
- `limit_up/limit_down`
- `published_at/available_at/ingested_at`
- `provider/source_revision`

数据进入正式使用前通过：Schema、唯一性、交易日历、价格关系、缺失、异常值、覆盖率和时间安全检查。

## 4. 时点与 A 股执行约束

- 日线信号默认在交易日收盘数据可用后生成。
- 回测默认在下一交易日按可执行价格模型成交。
- 买入后遵守 T+1 卖出限制。
- 停牌、涨跌停无法成交时保留订单状态，不假设成交。
- 手续费、印花税和滑点按版本化成本模型计算。
- 退市股票和历史指数成分必须保留，避免幸存者偏差。
- 财务或事件数据使用当时实际公开时间，不使用报告期结束日替代可用时间。

## 5. 分级验证漏斗

```mermaid
flowchart LR
    A[规则静态检查] -->|通过| B[微型固定样本]
    B -->|逻辑正确| C[代表性时期快速筛选]
    C -->|有基本信号| D[全市场历史回测]
    D -->|达到稳定性要求| E[样本外/滚动验证]
    E -->|通过| F[当前市场后台模拟]
    F -->|持续稳定| G[推荐启用]
```

### L0 静态检查

验证类型、字段、单位、窗口、表达式、数据依赖和未来信息。目标耗时小于 1 秒。

### L1 微型固定样本

使用包含涨跌停、停牌、复权和边界日期的固定股票片段，验证预期交易序列。目标耗时数秒。

### L2 快速筛选

选择牛市、熊市、震荡和异常波动的代表时期及分层股票样本。明显无效候选在这里淘汰。

### L3 完整回测

运行完整股票池和可用历史，计算组合与分层结果。

### L4 样本外与滚动验证

候选产生和参数选择区间与最终验证区间隔离，使用 walk-forward 验证跨时间稳定性。

### L5 后台模拟

使用之后真实到达的数据产生影子建议，验证数据可用性、延迟和实盘约束。

## 6. 评价维度

不得只按收益排序。至少评估：

- 年化收益和基准超额。
- 最大回撤、波动和下行风险。
- 交易次数、持有期、换手和容量代理。
- 胜率、盈亏比和收益分布。
- 交易成本敏感性。
- 不同年份、行业、市值和市场环境的稳定性。
- 参数邻域稳定性。
- 样本外和后台模拟偏离。
- 数据缺失、不可成交和异常行情影响。

最终门槛应在第一批真实基准策略上校准，不在文档中预设一个万能收益率。

## 7. 防止过拟合

- 每个模糊概念只生成少量有语义依据的候选。
- 使用参数范围稳定性，不选择孤立的历史最优点。
- 记录尝试过的全部候选，防止只报告成功结果。
- 保留独立样本外区间；验证失败后不能反复查看并继续调参而仍称为样本外。
- 多重尝试需要调整评估标准并报告搜索规模。
- 优先更简单、交易成本更低、跨环境更稳定的规则。
- 规则必须有可解释机制，纯相关性挖掘不能直接启用。

## 8. 性能设计

数据规模本身不是首要风险，重复计算和组合爆炸才是。

### 8.1 列式存储与分区

- 行情按市场、频率、年份或日期分区保存为 Parquet。
- 只读取规则需要的列和日期范围。
- PostgreSQL 保存元数据，不承担大规模时序扫描。

### 8.2 特征预计算

- 均线、成交量基线、波动率、滚动高低点等通用特征按版本计算。
- 同一特征被多个规则复用。
- 每日只增量更新受新数据影响的窗口。
- 特征定义、输入数据版本和实现版本共同形成缓存键。

### 8.3 两阶段引擎

- 向量化引擎用于批量信号筛选和参数候选淘汰。
- 事件驱动组合模拟只用于通过快速筛选的候选，处理 T+1、不可成交和资金约束。

### 8.4 缓存与复用

回测缓存键至少包含：

- RuleVersion 校验和。
- DatasetVersion 校验和。
- 股票池、日期范围和市场环境版本。
- 成本、执行和风险模型版本。
- 回测引擎版本。

缓存键未变化时直接复用结果；新增一天数据时只计算增量和受影响区间。

### 8.5 并行与调度

- 按规则、市场切片或时间切片并行，合并前保证结果确定性。
- Web 请求和持仓风险任务拥有最高资源优先级。
- 大规模完整回测默认在空闲或夜间运行。
- Worker 配置 CPU、内存和并发上限，达到上限时排队而不是拖垮机器。

### 8.6 LLM 与回测隔离

LLM 只在规则形成前调用一次或少量几次。回测循环不得调用 LLM。相同规则输入必须由确定性程序产生相同信号。

## 9. 硬件与容量

个人日线版建议：

| 资源 | 最低 | 推荐 |
|---|---:|---:|
| CPU | 4 核 | 8 核以上 |
| 内存 | 8 GB | 16 GB |
| 可用 SSD | 30 GB | 100 GB |
| GPU | 不需要 | 不需要 |

约 5,000 只股票、10 年日线是千万级记录，原始列式行情通常为数 GB；加上复权、特征、多个数据版本和回测制品，按 50～100 GB 规划。

32 GB 以上内存、服务器或分布式计算只在分钟级数据、本地大模型或大规模组合搜索进入范围后评估。

## 10. 性能目标

- 已缓存今日页首屏：P95 < 2 秒。
- 单只股票确定性分析：P95 < 5 秒。
- 文章提交：P95 < 2 秒，异步继续。
- L0/L1 检查：秒级。
- 单规则快速筛选：目标几十秒到数分钟。
- 完整日线回测：允许后台运行数分钟到几十分钟。
- 每日全市场扫描：缓存特征后目标在几分钟内完成。

具体目标必须在选定数据源和首台目标机器上通过基准测试确认。

## 11. 可复现制品

每次正式验证输出：

- 完整运行清单和校验和。
- 数据覆盖与质量报告。
- 规则编译结果。
- 信号和成交摘要。
- 分段和样本外指标。
- 失败或阻断原因。
- 生成时间、耗时和资源用量。

任何结论都应能在新数据库和相同版本行情制品上确定性重建。
