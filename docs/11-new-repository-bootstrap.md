# 新仓库启动说明

状态：`Draft v0.1`

## 1. 目的

本蓝图当前暂存在旧项目工作区。正式开发时必须建立独立 Git 仓库，使新实现不依赖旧代码、旧数据库、旧前端或旧运行时。

## 2. 迁移方式

新仓库建立后：

1. 将本目录中的 `README.md` 复制为新仓库根 README。
2. 将本目录中的 `docs/` 整体复制到新仓库 `docs/`。
3. 确认文档内没有指向旧仓库的运行依赖。
4. 在新仓库补充许可证、贡献说明和工程命令。
5. 在第一个实现提交前完成 P0 文档评审。

不要复制：

- 旧仓库源代码、组件、路由、页面布局和样式。
- 旧数据库迁移、ORM、服务层和任务代码。
- 旧构建缓存、环境文件、密钥、原始文章或行情数据。
- 为兼容旧系统而存在的接口和状态。

## 3. 新仓库初始化检查

- [ ] Git 历史从新仓库开始。
- [ ] 默认分支受到保护，开发使用一个长期 MVP 分支。
- [ ] `.gitignore` 覆盖密钥、数据库、行情、文章、制品、缓存和本地路径。
- [ ] 示例配置只包含占位符。
- [ ] README 明确 Web 唯一入口和 v1 不自动交易。
- [ ] 本地开发环境可以从空目录和空数据库重建。
- [ ] 迁移、测试、类型检查、格式检查和浏览器测试命令已经定义。
- [ ] CI 不依赖开发者本地数据库或未提交制品。

## 4. 第一个工程提交

只包含：

- 目录骨架。
- 开发环境和依赖锁。
- 空的 Web/API/Worker 健康路径。
- PostgreSQL 第一条迁移。
- 测试和 CI 骨架。
- 本文档集。

不要在第一个提交中加入文章抓取、指标大全、策略库或兼容层。

## 5. 第一条纵向路径

实现顺序固定为：

```text
首次设置
→ RiskPolicyVersion
→ 空但真实的“今天”页
→ 后台 Worker 健康状态
→ 浏览器端验收
```

该路径通过后，再进入第一篇真实文章。

## 6. 旧项目的使用边界

旧项目只允许作为只读经验来源，用于回答：

- 哪些产品和架构方式已经证明过于复杂。
- 哪些真实文章和数据边界值得形成新的测试夹具。
- 哪些安全、时间和可追溯要求必须保留。

复用任何逻辑前必须先写出新系统中的业务需求和测试，再独立实现。默认不复用代码。

## 7. 建议的初始 ADR

新仓库创建时补充：

1. ADR-001：新建独立仓库而不是旧仓库分支。
2. ADR-002：模块化单体与 PostgreSQL 任务队列。
3. ADR-003：LLM 提案、确定性执行与解释边界。
4. ADR-004：Parquet + 单机列式分析架构。
5. ADR-005：规则正式启用必须有人确认。
6. ADR-006：Web 三入口和内部对象不外露。

ADR 记录理由和后果，不重复粘贴整份需求。

## 8. 启动完成的定义

只有在以下条件满足后才开始 P1：

- 新仓库路径和远程仓库明确。
- 文档已迁入且链接通过。
- P0 样本和供应商试验有负责人和验收方式。
- 新仓库没有运行时引用旧项目。
- 用户确认仍采用 A 股、日线、人工执行的 MVP 边界。
