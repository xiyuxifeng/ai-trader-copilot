# 已冻结决策、风险与待定项

状态：`Draft v0.1`

## 1. 已冻结的产品决策

| 决策 | 结果 | 原因 |
|---|---|---|
| 新旧系统关系 | 新建独立仓库和运行时 | 避免旧领域、UI 和流程继续影响产品 |
| 目标用户 | 单个个人投资者 | 先验证核心价值，避免权限和协作复杂度 |
| 市场与频率 | A 股、日线、收盘后 | 控制数据、执行和性能复杂度 |
| 交易执行 | 用户最终决定，不自动下单 | 保留安全和责任边界 |
| AI 角色 | 理解、提取、提出假设和解释 | 计算与资格判断必须确定性 |
| 自动化策略 | 人只处理例外 | 降低使用和维护成本 |
| 规则发布 | AI 不得自动正式启用重大规则 | 防止静默改变交易行为 |
| UI | 今天、分析、我的交易员三个入口 | 直接围绕用户任务设计 |
| 设置 | 3 分钟、最多五个初始化问题 | 默认即可使用 |
| 架构 | 模块化单体 + 独立 Worker | 简单、可测试，足以支持 MVP |
| 回测 | 必须，且分级执行 | 筛选文章假设并控制资源 |
| 持续进化 | 版本化、评测、模拟、确认、回滚 | 适应市场但不失控 |

## 2. 允许延后的选择

以下事项不阻塞需求和架构，可以在 P0 用实际试验决定：

- 具体 LLM 供应商和模型组合。
- 正式行情数据供应商。
- React 构建框架和 UI 组件库。
- DuckDB 与 Polars 的具体职责分工。
- 通知渠道。
- 本地密钥存储实现。
- 市场状态识别的首版算法。

延后不等于任意选择；每项选择必须满足已经冻结的 Adapter、评测和安全契约。

## 3. 不应提前决定的内容

- “放量”等概念的唯一固定参数。
- 每篇文章必须产出的规则数量。
- 统一适用于所有策略的收益率门槛。
- 尚无规则需求的数据源和指标库。
- 分钟级、券商、多用户或分布式计算架构。

这些决定必须由真实文章、数据质量、验证结果和用户任务驱动。

## 4. 主要风险

### R1 行情数据许可、质量和时点

影响：最高。错误或不可追溯数据会使全部回测和建议失效。  
控制：P0 对比供应商；统一 `available_at`；覆盖和修订监控；供应商 Adapter；正式建议阻断门。

### R2 模糊概念被伪精确化

影响：最高。系统可能生成看似严谨、实际没有语义依据的规则。  
控制：原文证据、有限候选、可观察性分类、无法量化时降级为知识、固定评测集。

### R3 回测过拟合

影响：最高。大量候选和参数可能偶然得到优秀结果。  
控制：限制搜索空间、记录全部尝试、样本外、滚动验证、参数邻域、后台模拟和简单性优先。

### R4 自动化造成静默错误

影响：高。低人工介入不能变成低可控性。  
控制：风险内核、自动暂停、重大规则确认、版本和回滚、拒绝建议、例外去重。

### R5 LLM 不稳定和成本变化

影响：中高。供应商升级会改变提取结果或成本。  
控制：Provider Adapter、Schema、缓存、固定回归、模型版本、成本硬预算和可恢复任务。

### R6 产品再次变复杂

影响：高。内部模块可能重新泄漏到 UI。  
控制：三入口、交互预算、非开发用户测试、内部术语黑名单、UX Gate 与每页单一主操作。

### R7 回测拖慢日常使用

影响：中。后台研究可能占满 CPU、内存和磁盘。  
控制：分级验证、缓存、前台优先级、Worker 资源上限、夜间调度和磁盘保护。

### R8 文章获取和版权

影响：中。并非所有来源允许抓取和长期存储。  
控制：MVP 优先用户粘贴/上传；来源契约验证后才做抓取；保存许可、引用和最少证据。

### R9 用户把建议当成保证

影响：高。条件化判断可能被理解为确定结果。  
控制：显示有效期、数据时间、失效条件和风险；禁止保证性文案；用户最终决定；不自动下单。

## 5. 开发前仍需完成但不要求用户回答的研究项

由开发阶段自动完成并形成 ADR：

1. 两个候选行情供应商的真实覆盖、时点、许可和成本验证。
2. 两到三个 LLM 在固定文章集上的结构化提取、证据和成本比较。
3. 目标机器上千万级日线数据的扫描、特征和回测基准。
4. 首批模糊概念的候选操作化模板。
5. 真实用户完成三个核心任务的低保真可用性测试。

只有会改变产品边界、资金风险或用户交易风格的结果才需要用户决策。

## 6. 未来演进顺序

MVP 稳定后建议按价值和风险顺序评估：

1. 更丰富的财务、行业和事件数据。
2. 组合级风险和相关性分析。
3. 文章来源自动订阅。
4. 更细的市场状态和行业轮动分析。
5. 分钟级提醒。
6. 券商只读持仓同步。
7. 经独立安全评审后，再讨论任何自动执行能力。

每一项都是新范围，不因架构支持就自动进入计划。
