# 产品需求文档（PRD）

状态：`Draft v0.1`  
目标版本：`MVP`  
目标周期：10～14 周

## 1. 背景与问题

个人投资者能够接触大量交易文章，但很难稳定完成以下工作：

- 判断文章是有效经验、市场评论、营销内容还是重复信息。
- 将“放量、强势、情绪转暖、重要压力位”等表达转换成可验证条件。
- 检查观点需要哪些行情或事件数据，以及数据是否真实可得。
- 使用符合 A 股制度和时间约束的方式验证观点。
- 把有效规则用于当前股票，同时保留证据、适用环境和失效条件。
- 持续复盘并淘汰失效规则，而不是积累越来越多的静态规则。

现有复杂研究平台通常把数据、参数、流程编排和判断工作交给用户，导致系统理论上完整、实际无法使用。

## 2. 产品目标

构建一个低人工介入的 AI 交易决策辅助系统，使用户能够：

1. 提交文章后，不参与中间研究流程也能得到可信处理结果。
2. 输入股票并说明是否持仓后，获得有条件、有风险边界、有时点说明的操作建议。
3. 每天打开首页即可看到候选机会、持仓风险和真正需要处理的例外。
4. 让系统通过新文章、市场表现和交易结果持续改进规则与分析能力。

## 3. 非目标

MVP 明确不做：

- 券商连接、自动下单、自动资金调度。
- 分钟级、高频、盘口或 tick 级交易。
- 多用户团队协作、租户和复杂权限系统。
- 社交、跟单、策略市场或公开投资建议发布。
- 通用量化编程平台和无限参数搜索器。
- 让 LLM 直接遍历历史数据或直接计算买卖信号。
- 强制把每篇文章转换成交易规则。

## 4. 目标用户与核心任务

### 4.1 目标用户

- 有自己的文章来源和交易经验，但不具备完整量化研究能力的个人投资者。
- 愿意最终自行决定交易，但不愿维护复杂数据、回测和规则工程流程。
- 主要使用 A 股日线和收盘后决策。

### 4.2 核心任务

- “帮我学习这篇文章，自动判断有用的部分。”
- “分析这只股票，我现在应该观察、持有、减仓还是退出？”
- “今天有哪些股票或持仓需要我关注？”
- “最近学到了什么？哪些规则已经失效？”

## 5. 产品成功定义

MVP 成功必须同时满足：

- 新用户不阅读说明书，3 分钟内完成初始化。
- 30 秒内发起一次股票分析。
- 1 分钟内提交一篇文章，之后不需要手工推动处理阶段。
- 普通页面不出现 JSON、UUID、校验和、数据表名、任务编排名或内部状态码。
- 至少一篇真实文章完成“证据 → 候选规则 → 回测 → 后台模拟 → 推荐启用”的闭环。
- 至少一只真实股票完成“行情 → 规则评估 → 建议 → 失效条件 → 后续复盘”的闭环。
- 没有例外时，用户无需进行任何维护操作。
- 所有建议都能追溯到数据截止时间、规则版本和证据来源。

## 6. 功能需求

### FR-01 首次设置

首次使用最多确认五项：

1. 交易市场，MVP 默认 A 股。
2. 操作周期：短线、波段或中长线。
3. 风险偏好：保守、均衡或进取。
4. 单只股票最大仓位。
5. 提醒时间与方式。

要求：

- 每项有安全推荐默认值，可直接完成。
- 技术参数由系统根据选择生成，不要求用户逐项配置。
- 设置完成后可以随时修改，但日常使用不依赖进入设置页。

### FR-02 文章导入

用户可以通过粘贴正文、提交链接或上传受支持文档导入文章。

系统自动：

- 获取并保存来源、正文和内容指纹。
- 检测重复、近似重复和内容完整性。
- 识别与交易无关、仅有背景价值、可形成假设或可直接执行的内容。
- 提取原文证据，禁止只保存脱离原文的总结。
- 后台串联后续研究，不要求用户启动多个任务。

### FR-03 内容价值判断

每篇文章必须被自动归入以下结果之一：

- `规则研究`：包含可以研究的交易条件。
- `分析知识`：对解释市场有帮助，但不直接产生规则。
- `等待数据`：观点可研究，但缺少必要数据。
- `重复合并`：与已有内容实质重复，仅补充证据。
- `自动归档`：无交易价值、无法验证、广告或噪声。

系统必须给出简短原因；分类结果默认不要求用户确认。

### FR-04 模糊概念自动处理

对于“放量、强势、超跌、龙头、重要支撑”等概念，系统必须：

- 保存原始措辞和上下文。
- 判断是否能拆解为可观察量。
- 生成数量受限、具有语义依据的候选定义。
- 明确每个定义需要的数据、时间窗口和适用范围。
- 自动验证候选，而不是要求用户选择参数。
- 无法可靠量化时降级为分析知识，不进入确定性交易规则。

### FR-05 规则生成与验证

可执行规则必须包含：

- 适用标的和市场环境。
- 入场、持有、退出和失效条件。
- 数据字段、频率和可用时间要求。
- 风险限制、交易成本和执行假设。
- 原文证据及推导说明。
- 版本、状态和验证结果。

LLM 只能生成结构化候选；确定性程序负责语法检查、指标计算、回测和资格判定。

### FR-06 股票分析

用户输入股票代码、名称或自然语言问题。系统仅在必要时询问：

- 是否持仓。
- 持仓成本和仓位，可选；缺失时不提供精确仓位建议。

第一屏必须显示：

- 当前建议：观察、等待、持有、减仓或退出等条件化结论。
- 适用时间和行情截止时间。
- 风险等级和最重要的失效条件。
- 下一步动作及触发条件。

用户展开后可以查看：规则依据、关键数据、冲突观点、历史表现和文章证据。

### FR-07 今日页

首页只回答四个问题：

1. 今天市场处于什么状态？
2. 哪些候选股票满足已启用规则？
3. 哪些持仓出现风险或需要行动？
4. 是否有必须由用户处理的例外？

没有信号时必须明确显示“今天没有满足条件的机会”，不得用低质量候选填充页面。

### FR-08 持仓与结果记录

MVP 支持用户轻量维护持仓：股票、方向、数量或仓位、成本、建仓日期。

- 可以手工添加或通过受支持模板导入。
- 不要求连接券商。
- 用户可以用一次选择记录“执行、部分执行、未执行”。
- 系统根据后续行情自动完成建议表现复盘。

### FR-09 我的交易员

该页面展示：

- 当前启用的交易规则和适用环境。
- 后台正在学习、验证和模拟的数量及进度摘要。
- 最近自动淘汰、暂停和推荐升级的规则。
- 周度学习与表现报告。

页面不暴露研究流水线内部对象；详细证据按需展开。

### FR-10 自动演进

系统持续运行两个闭环：日常决策闭环与研究演进闭环。

- 新知识产生候选规则或补充已有规则证据。
- 新规则先离线验证，再后台模拟。
- 旧规则按市场环境和实际表现持续监控。
- 表现恶化、数据失效或适用条件不再满足时自动暂停。
- AI 可以提出升级，但不能静默修改已启用规则。
- 重大规则启用以一条摘要和一次确认完成，支持批量确认。
- 每次升级保留旧版本并支持回滚。

### FR-11 例外收件箱

只有系统不能安全自动处理且会影响实际决策的事项才能进入例外收件箱，包括：

- 会改变风险边界的规则升级。
- 两种含义均有证据但代表不同交易风格的关键歧义。
- 数据源长期失效并影响当前建议。
- 用户设置之间发生冲突。

要求：

- 同一事项只显示一次。
- 每次只问一个业务问题。
- 提供推荐选项和影响说明。
- 可以稍后处理，不阻塞无关功能。

### FR-12 通知与报告

- 默认只发送需要行动的持仓风险和重大系统异常。
- 学习过程不逐条通知，以日摘要或周报告汇总。
- 用户可关闭非风险通知。
- 报告使用业务语言，不展示内部任务日志。

## 7. 自动化政策

| 类别 | 默认动作 | 用户介入 |
|---|---|---|
| 无关、重复、无效文章 | 自动归档或合并 | 不需要 |
| 可研究但尚未验证 | 自动生成候选并验证 | 不需要 |
| 缺少非关键数据 | 进入等待队列并自动重试 | 不需要 |
| 验证失败的规则 | 自动淘汰并保留记录 | 不需要 |
| 验证通过的规则 | 自动进入后台模拟 | 不需要 |
| 已启用规则表现恶化 | 自动暂停并通知 | 不需要确认暂停 |
| 重大新规则正式启用 | 汇总推荐 | 一次确认 |
| 实际交易执行 | 给出条件化建议 | 用户最终决定 |

目标：90% 以上的文章和研究任务不产生用户待办。

## 8. 非功能需求

### NFR-01 可解释与可追溯

- 每条建议记录行情截止时间、数据版本、规则版本和生成时间。
- 每条规则能够回溯到文章证据或明确的系统先验。
- AI 总结不能替代原始证据。

### NFR-02 安全与真实性

- 数据不足、过期或不满足覆盖要求时禁止输出确定性建议。
- 禁止使用未来信息或当前不可得信息。
- 不把低置信结果包装成精确结论。
- 风险限制优先于策略信号。

### NFR-03 性能

- 已缓存的今日页首屏：P95 小于 2 秒。
- 单只股票基础分析：P95 小于 5 秒；需要 LLM 解释时先返回确定性结果。
- 文章提交响应：小于 2 秒，后续异步处理。
- 后台回测不得造成前台交互 P95 超过预算。

### NFR-04 可用性

- 主导航不超过三个入口，设置使用独立图标入口。
- 正常任务不超过三次操作。
- 每个页面只有一个视觉主操作。
- 支持 375、768、1024、1440 像素宽度。
- 键盘可操作，正文对比度至少 4.5:1，颜色不是唯一状态编码。

### NFR-05 可维护与可进化

- 模型、行情源、文章源和通知服务通过明确适配器隔离。
- 领域逻辑不依赖 HTTP、ORM、LLM 或具体供应商 SDK。
- 规则和能力均版本化，升级前可评测，升级后可回滚。
- 一个业务意图只有一条规范路径，不保留重复流程。

## 9. 产品指标

MVP 上线后关注：

- 无人工介入完成的文章比例。
- 从文章提交到分类完成的时间。
- 候选规则验证淘汰率与进入模拟比例。
- 股票分析成功率和因数据不足拒绝率。
- 用户每天需要处理的例外数量。
- 建议证据链完整率，目标 100%。
- 新用户完成初始化和首次分析的成功率。
- 启用规则在不同市场环境中的稳定性与回撤。

产品指标不以“生成规则数量”或“买入建议数量”为成功标准。
