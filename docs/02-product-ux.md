# 产品体验与 UI 规范

状态：`Draft v0.1`

## 1. 体验目标

用户感受到的是一个已经替他完成研究工作的私人交易员，而不是一组需要编排的工具。

体验顺序固定为：

```text
结论 → 行动条件 → 风险与失效 → 可选证据 → 内部技术细节不可见
```

## 2. 信息架构

主导航只有三个入口：

1. **今天**：市场状态、候选机会、持仓风险、必须处理的例外。
2. **分析**：输入一只股票或问题，获得当前建议。
3. **我的交易员**：已启用规则、学习进度、表现和规则升级。

辅助入口：

- 设置：右上角入口，不占主导航。
- 帮助：上下文说明，不建立复杂帮助中心。
- 文章导入：位于“我的交易员”的主要操作，也可在全局快捷入口出现。

普通用户界面禁止出现：

- JSON、UUID、校验和、数据库字段和供应商原始响应。
- Campaign、Checkpoint、Protocol、Finding 等内部治理名词。
- 复制内部 ID、手动选择数据集、手动启动流水线。
- 提示词、模型温度、Token 上限或回测引擎配置。
- 仅开发人员理解的英文状态码和任务编号。

## 3. 首次使用

### 3.1 初始化流程

采用渐进披露，总时间不超过 3 分钟：

1. 欢迎页说明系统能做什么以及不自动下单。
2. 选择交易周期和风险偏好。
3. 接受或调整单只股票最大仓位。
4. 选择提醒时间；其余使用推荐值。
5. 直接进入“分析第一只股票”或“导入第一篇文章”。

规则：

- 可以跳过非必要步骤。
- 每页最多一个主问题和一个主按钮。
- 默认值旁说明实际影响，不解释实现参数。
- 不播放强制教程，不使用无法关闭的引导遮罩。

## 4. 页面规格

### 4.1 今天

页面从上到下：

1. 数据截止时间和市场状态一句话。
2. 持仓需要行动的事项，按风险优先排序。
3. 满足规则的候选机会。
4. 需要用户处理的例外；没有则不显示该区域。
5. 系统学习摘要，以一行折叠信息呈现。

空状态必须有明确含义：

- “今天没有持仓需要处理。”
- “今天没有股票满足你的规则。”
- “所有后台研究正常，无需处理。”

不得使用空图表或无意义 KPI 填充页面。

### 4.2 分析

初始页面只有一个主要输入框：

> 输入股票代码、名称，或者直接提问

识别股票后，只询问“是否持仓”；成本和仓位可选。

结果首屏：

- 建议动词和一句话结论。
- 当前价格、行情日期和建议有效期。
- 触发行动的条件。
- 最重要的失效条件和风险。
- 一个主操作，例如“加入观察”或“更新持仓”。

折叠详情：

- 为什么这样判断。
- 匹配和冲突的规则。
- 关键行情与历史表现。
- 文章证据与规则版本。
- 数据完整性说明。

当信息不足时，使用明确拒绝态：

> 当前数据不足，暂不生成操作建议。已在后台补充数据，不影响其他功能。

### 4.3 我的交易员

默认显示三项：

- 当前启用规则及适用市场环境。
- 本周自动学习摘要。
- 值得关注的规则升级或暂停记录。

文章处理入口：粘贴、链接或上传后点击“交给交易员学习”。

处理结果示例：

> 已处理 12 篇：7 篇作为知识保存，3 篇重复合并，2 条规则进入验证。无需处理。

规则详情使用业务语言，默认不展示公式；需要时可展开“计算方式”。

### 4.4 设置

设置页最多四组：

1. 我的交易偏好。
2. 风险与仓位。
3. 提醒方式。
4. 数据与 AI 服务。

约束：

- 首屏可编辑项不超过五个，总设置项原则上不超过十个。
- 数据和 AI 服务只显示“正常、需要处理、不可用”等状态。
- API Key 流程为粘贴、检测、保存；保存后仅显示掩码。
- 高级参数不进入普通设置页。
- 修改风险偏好后，由系统重新生成相关参数并展示影响摘要。

## 5. 交互预算

| 用户任务 | 最大操作量 |
|---|---:|
| 查看今天是否需要行动 | 打开首页 |
| 分析股票 | 输入 + 是否持仓 |
| 导入文章 | 粘贴/上传 + 提交 |
| 记录是否执行建议 | 一次选择 |
| 启用推荐规则 | 阅读摘要 + 一次确认 |
| 解决文章歧义 | 一次只回答一个问题 |

需要超过三步的正常任务视为产品缺陷，不通过 UX Gate。

## 6. 视觉与组件原则

- 风格：专业、克制、数据优先，支持浅色和深色模式。
- 字体：优先系统字体；数字使用等宽数字特性，不引入装饰字体。
- 主色只用于主操作和当前选择；风险状态同时使用文字和图标。
- 一个页面最多一个高强调 CTA。
- 卡片仅用于真正独立的摘要或操作区域，禁止卡片套卡片。
- 动画控制在 150～300ms，遵循 `prefers-reduced-motion`。
- 图标统一使用同一 SVG 图标库，不使用 emoji 作为功能图标。
- 所有输入有可见标签，不能只依赖 placeholder。
- 点击目标在触屏环境约 44×44px，键盘焦点清晰可见。

## 7. 文案规则

文案必须说明：发生了什么、用户是否要处理、下一步是什么。

推荐：

- “这条规则未通过样本外验证，已自动淘汰。”
- “行情数据截止到 2026-10-22 收盘。”
- “跌破 18.40 元后，当前持有逻辑失效。”

禁止：

- “任务执行失败：VALIDATION_STAGE_3_ERROR”。
- “Campaign 尚未满足 Checkpoint 条件”。
- “系统认为一定会上涨”。

建议必须使用条件化语言，区分事实、计算结果和 AI 解释。

## 8. 响应式与无障碍

- 断点验证：375、768、1024、1440px。
- 移动端保留全部关键结论和操作，不把核心功能放在 hover 中。
- 正常文本对比度至少 4.5:1。
- 状态不能只靠红色和绿色表达。
- 错误使用可被辅助技术读取的提示。
- 标题层级连续；主要区域使用语义化 HTML。
- 全部功能可用键盘完成，Tab 顺序与视觉顺序一致。

## 9. UX 验收测试

招募从未看过产品文档的测试者，验证：

1. 3 分钟内完成首次设置。
2. 30 秒内发起股票分析。
3. 1 分钟内完成文章提交。
4. 能准确复述建议、触发条件和最大风险。
5. 不需要理解规则版本、任务队列或数据工程术语。
6. 没有例外时，不会误以为自己还有工作未完成。

任一核心任务成功率低于 90%，或测试者必须阅读操作手册，UX Gate 不通过。
